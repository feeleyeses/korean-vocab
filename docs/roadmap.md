# 韩语词场产品路线图

## 现阶段：先把学习闭环做稳

### P0 交互与部署可靠性
- GitHub Pages 项目路径兼容：所有应用静态资源必须使用项目相对路径，避免 SSR 可见但 JS 未启动。
- 部署 smoke check 不再只验证 HTTP 200，而要验证主运行时 JS、增强脚本和数据文件都可读取。
- 核心交互验收：学习、记得/模糊/不认识、看答案、继续、收藏、复习入口、词库展开、移动端导航。

### P1 学习卡 V2
目标：单张卡首先完成“认词 → 读音 → 核心义 → 例句”，增强内容按需出现。

一级信息（始终可见/揭晓后优先）：
1. 韩文 headword
2. 实际读音 + 罗马音 + 词性
3. 当前释义
4. 韩文例句 + 中文翻译

二级信息（有可靠数据才显示）：
- 固定搭配 collocations
- 易混辨析 confusion note

三级信息（后续折叠）：
- 近义词 / 反义词
- 更多例句
- 口语/正式语体提示
- 完整多义拆解

规则：宁缺毋滥；无数据时隐藏模块，不自动凑内容。

### P1 词库/复习布局
- 复习入口稳定断点：宽屏 6 列、中屏 3 列、移动端 2/1 列。
- 已学词库筛选压缩为工具区，不让筛选占据页面主体。
- 已学词条视觉居中、卡片高度稳定、列表内部滚动。
- 本地学习档案与“下次复习”保持次级信息层级。

### P2 数据模型清理
当前运行 bundle 会按 headword 合并重复词条，这会把同形异词错误当作一词多义。

下一版正式数据模型必须至少包含：
- lexicalEntryId：词条唯一 ID
- lemma/headword：表记
- homographNo：同形异词编号（可空）
- pos
- pronunciation / romanization / soundRule
- levels[] / tracks[] / register
- senses[]：每个释义拥有独立 senseId
- collocations[]
- relations：synonym / antonym / confusedWith
- source / verifiedAt / verificationStatus

合并规则必须从“headword 相同就合并”改成“lexicalEntryId 决定词条；只有明确属于同一词条的 senses 才合并”。

## 词汇量：从 596 词走向可长期使用的词库

当前基线（迁移版本）：约 596 个唯一词条、642 个释义；其中约 552 个属于 TOPIK 轨道。页面目标总量为 6,000，但当前收录远未达到该规模。

### 阶段 A：1,000 个高质量词条
重点：TOPIK 1–2 + 高频日常词。
要求：核心义、词性、例句、基础读音完整；高频词优先补搭配和易混辨析。

### 阶段 B：2,500 个词条
重点：TOPIK I 基础覆盖完成，并补齐 TOPIK 3–4 高频阅读/写作词。
要求：开始系统建设一词多义、音变和书面语搭配。

### 阶段 C：4,000 个词条
重点：TOPIK 4–5，社会、教育、经济、环境、职场等高频主题词。
要求：正式语体、常见搭配、同义/近义辨析成为常规字段。

### 阶段 D：6,000 个核心词条
重点：TOPIK 1–6 完整主干库。
注意：网络词、饭圈/K-HipHop 等真实语境词应作为独立 track 扩充，不拿来虚增 TOPIK 覆盖率。

## 将来：从“背单词页”升级成个人韩语词汇系统

### V1.5 数据层
- 将词库从编译后的 JS bundle 迁出为独立 JSON/SQLite-like 数据资产。
- 支持增量更新词库，而无需每次重构整站 bundle。
- 建立自动审计：重复 ID、同形异词、空释义、重复例句、等级冲突、来源缺失。

### V1.5 学习体验
- 词汇详情页：一个词的读音、释义、搭配、辨析、例句、多义学习历史集中查看。
- 例句关键词高亮：韩文目标形式与中文对应义同步强调。
- 复习模式按问题类型拆分：认义、选义、听音、音变、搭配、多义。

### V2 个性化
- 根据“忘记 / 模糊 / 混淆 / 多义漏选”自动生成个人弱项包。
- 按 TOPIK 等级、考试日期和每日时间预算计算学习计划。
- 区分“认识”“会用”“听得出来”三类掌握度。

### V2 内容扩展
- 日常真实语境库：常用口语、网络表达、缩略语。
- 主题词包：校园、旅行、求职、金融、音乐/K-HipHop 等。
- 所有扩展 track 与 TOPIK 主库分开统计，保证备考数据可信。

## 验收原则
1. 功能先于视觉：核心按钮失效时停止新功能扩张。
2. 数据质量先于词数：1,000 个可靠词优于 6,000 个未经校验的词。
3. 移动端优先：学习主卡和操作区必须在手机上保持可操作。
4. 信息按需出现：卡片不做百科全书，增强信息有则展示、无则隐藏。
5. 每次部署必须经过数据审计 + 运行时资源 smoke check。
